# 公开课专项指南：信息技术融合 + 亮点提炼 + 说课要点

> 本文件是公开课三大专项的执行工具。原则：**技术为教学服务，亮点必须落地，说课讲"为什么"而不是背环节。** 使用者：🌟 公开课设计师、🎭 活动设计师、🔍 质检评审员。

---

## 一、信息技术融合设计

### 1.1 融合三问（每个技术点必须通过）

| 问题 | 不通过的后果 |
|------|-------------|
| ① 它解决什么教学问题？ | 答不出 → 删除该技术点 |
| ② 不用它会怎样？ | 没差别 → 删除（板书/实物更佳时优先线下） |
| ③ 设备故障怎么办？ | 没预案 → 赛课风险点，必须补纸质/板书替代 |

### 1.2 常用工具与适用场景速查

| 工具 | 最擅长的教学用途 | 典型环节 |
|------|----------------|---------|
| 希沃白板5-课堂活动（分类/竞赛） | 即时反馈、全班参与、游戏化 | 辨析、巩固练习 |
| 希沃白板-动画/蒙层 | 制造认知冲突、逐步揭示 | 情境导入、概念建构 |
| 实物展台 | 展示学生作品原貌、对比不同解法 | 动手操作后的交流 |
| 班级优化大师/随机点名 | 保证参与面公平、即时点评 | 全课穿插 |
| AI 工具（对话/绘图） | 提供初稿供批判、生成多方案供比较 | 探究课认知阻滞点 |
| 计时器/倒计时 | 活动节奏管理、限时挑战 | 小组任务 |
| 弹幕/投票器 | 匿名暴露真实想法 | 前测、观点分歧处 |

**学科示例**：
- 数学：几何画板动态演示"分割渐细"，比静态图更能建立极限直观
- 语文：蒙层逐步揭示关键词，引导"猜读—验证"
- 英语：AI 语音对话提供真实语用对象，但"跟读纠音"必须真人示范口型
- 科学：传感器实时采集数据，把"看数据"变成"看曲线变化"

### 1.3 分级融合策略（按公开课级别）

| 级别 | 技术融合度 | 要点 |
|------|-----------|------|
| 校级教研课 | 基础（课件+1-2个互动点） | 用得稳比用得多重要 |
| 县级公开课 | 中度（2-4个技术点+1个亮点技术） | 至少一个技术点直击本课难点 |
| 市级/省级赛课 | 深度（技术与认知设计咬合） | 技术使用本身构成教学创新点 |

### 1.4 写法规范（双语铁则同样适用）

- ✅ `希沃白板动画呈现"月饼渐少"过程——比静态图片更能让学生感受到"不够分"的紧迫`
- ❌ `运用信息技术与学科深度融合策略，增强课堂互动性`

**"不用技术"也是专业判断**，写明理由：
- ✅ `本环节不使用技术：折纸的触觉体验是屏幕替代不了的，实物操作更能建立"一半"的概念`

## 二、教学亮点与创新点提炼

### 2.1 亮点从哪里来（五个来源，按含金量排序）

1. **认知设计的巧劲**：在学生卡点上做的设计文章（如"认知阻滞点"让学生必须自己想）
2. **证据链完整**：学情预判→设计回应→评价验证，环环有据（评委最认这个）
3. **技术的教学化改造**：不是用了新工具，而是把工具用在了别人没想到的教学关节上
4. **结构创新**：环节顺序、扶放节奏、差异化路径的独特安排
5. **真情境真任务**：把知识放进学生真的在乎的问题里

### 2.2 亮点表述公式

```
亮点名称（4-8字短语）+ 一句话说明（它为什么值得注意）+ 体现在哪个环节（必须可指认）
```

示例：

| 亮点 | 一句话说明 | 体现在哪个环节 |
|------|-----------|---------------|
| 让"一半"看得见 | 全程折纸涂色，抽象分数变成手里的操作，符号最后才出现 | 环节②③ |
| 评价长在过程里 | 随机点名+三级点评+课末检测，每15分钟一次反馈，不留"下课才知道没懂" | 全课 |
| 技术用在刀刃上 | 动画只干一件事：制造"不够分"的认知冲突，其余环节坚决不用 | 环节① |

### 2.3 提炼流程

1. 通读全案，标出"别人不容易想到/做到"的设计点
2. 每个设计点回答：评委为什么会在意它？
3. 合并同类，保留 3-5 条（少于3条单薄，多于5条稀释）
4. 每条找"体现在哪个环节"——找不到落点的删除（SKILL.md 8.6 军规）

### 2.4 禁忌

- ❌ 编造课里没有的"亮点"（评委追问即穿帮）
- ❌ "运用了先进教学理念"这类空话（所有课都能说=不是亮点）
- ❌ 把常规操作当亮点（"使用了多媒体课件"在今天是标配不是亮点）

## 三、说课要点（设计说明）

### 3.1 六说框架与内容要求

| 说 | 评委想听什么 | 写法要点 |
|----|-------------|---------|
| 说学情 | 你凭什么这样设计 | 学生起点+卡点，设计如何精准回应 |
| 说目标 | 目标从哪里来 | 课标锚点+学情依据，为什么是这几个目标 |
| 说教法学法 | 教学主线是什么 | 扶放主线，每阶段为什么这样取舍 |
| 说过程 | 逻辑链是否自洽 | 环节推进逻辑，每步如何指向核心问题 |
| 说技术 | 技术是否为教学服务 | 每项技术的教学目的+故障预案 |
| 说评价 | 怎么证明学会了 | 评价与目标的一一对应关系 |

### 3.2 说课稿与教案的区别

- 教案回答"这节课**做什么**"；说课回答"**为什么**这样做"
- 每说 2-3 句，总计不超过一页——说课要点是"提词器"，不是逐字稿
- 预设评委追问：最可能被追问的点（技术故障？时间不够？学生答不出？）→ 已在"教学实施问题预判"准备

### 3.3 常见追问与应答锚点

| 评委追问 | 应答锚点（指向教案哪部分） |
|---------|--------------------------|
| "如果设备坏了怎么办？" | 教学准备-技术预案 |
| "如果学生答不到点上？" | 教学实施问题预判-调整预案 |
| "怎么知道学生学会了？" | 评价设计-后测达标线 |
| "这节课的创新点是什么？" | 教学亮点与创新点（可逐条指认环节） |
| "学困生怎么办？" | 差异化支持-基础路径 |

## 四、与主流程的衔接

| 专项 | 触发时机 | 前置条件 |
|------|---------|---------|
| 逐环节技术标注 | Step 2a 活动设计时同步标注 | 教学环境已知 |
| 技术总览+预案 | Step 3c/3d | 全部环节技术点已定 |
| 亮点提炼 | Step 3a（一致性审查通过后） | 设计已稳定，避免提炼后大改 |
| 说课要点 | Step 3b（亮点定稿后） | 亮点是"说过程""说技术"的素材 |
