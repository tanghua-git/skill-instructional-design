# Word 排版规范：Markdown 语法约定 + 版式标准

> 本文件是 `scripts/build_docx.py` 排版引擎的使用契约。**教案组装（Step 4）前必读。** Agent 生成的 Markdown 必须严格遵循本约定，转换器才能输出规范版式；违反语法的标记会被当作普通文本，破坏排版。

---

## 一、支持的 Markdown 子集（完整清单）

| 语法 | 渲染效果 | 使用位置 | 约束 |
|------|---------|---------|------|
| `# 标题` | 文档主标题：黑体二号居中 | 文档第 1 行 | **仅允许一个** |
| `@info 内容` | 信息行：楷体四号居中 | 主标题之后 | 每行 ≤32 字（超宽自动降字号），建议 2 行 |
| `## 标题` | 一级章节：黑体三号 | 〇/一/二…十/附录 | 含"附录"二字自动另起一页 |
| `### 标题` | 二级小节：黑体四号 | 环节① 标题 | — |
| `\| 表格 \|` | 表格（首行为表头，自动底纹） | 各章节 | 见"二、三种表格" |
| `> 内容` | 引用块：楷体灰字+◆前缀+缩进 | 扶放角色/信息技术应用等说明 | 连续 `>` 行自动合并 |
| `- 内容` / `1. 内容` | 项目符号列表 | 目标、重难点等 | — |
| `**加粗**` | 加粗 | 任意文本处（含表格内） | — |
| `---` | 忽略（不渲染） | — | 不要用来制造分隔线 |
| 普通段落 | 正文：仿宋小四，首行缩进2字符 | 大部分内容 | — |

**不支持的语法**（出现即排版事故）：代码块 ``` 、标题加粗标记 `**#**`、链接 `[]()`、图片 `![]()`、HTML 标签、制表符缩进。

## 二、三种表格（转换器自动识别）

### 2.1 思路主线流程图（自动渲染为竖向流程框图）

**触发条件**：章节标题含"思路主线"，其下第一个两列表格。

```markdown
## 〇、这节课的思路主线（一图看懂）

| 环节 | 为什么这样安排 |
|---|---|
| 环节① 情境导入·分月饼（5分钟） | 用熟悉的分月饼场景勾起兴趣，摸清学生原有想法 |
| 环节② 动手操作·折出二分之一（12分钟） | 让学生发现"一半"要靠分，旧想法不够用了 |
```

渲染效果：每个环节一个框（标题行浅蓝底纹+黑体居中，"为什么"行正文），框间居中箭头 ↓。**环节名内必须含时间标注**，格式统一为"环节N 名称（X分钟）"。

**严禁**：用 `→` 横排文字画流程图（中英文混排必然错位）、用图片当流程图、用空格对齐。

### 2.2 教学过程四列表（自动设置列宽 39%/26%/17%/17%）

**触发条件**：表头恰好为"环节流程（学生做什么）| 为什么这样设计 | 教师行为 | 学生行为"。

```markdown
### 环节① 情境导入·分月饼（5分钟）

| 环节流程（学生做什么） | 为什么这样设计 | 教师行为 | 学生行为 |
|---|---|---|---|
| 看动画：4个月饼分给2人……最后只剩1个怎么分？ | 从熟悉的"一半"出发，新课有落脚点 | 播放动画、追问"怎样分才公平" | 观看、回答、说出"平均分" |

> 这一步的角色：先扶着走——教师示范，学生看和听（扶放有度第一阶段）。

> 信息技术应用：希沃白板动画呈现"月饼渐少"，比静态图更能制造认知冲击。
```

**约定**：表头写法必须与上面逐字一致（含括号）；单元格内不手动换行（长内容自动换行）；表格后的说明统一用 `>` 引用块。

### 2.3 通用表格（自动表头底纹）

其余所有标准 Markdown 表格，如亮点表、技术总览表。表头文字尽量 ≤6 字。

## 三、版式标准（转换器自动完成，无需手调）

| 项目 | 标准 |
|------|------|
| 纸张 | A4 纵向 |
| 页边距 | 上下 2.54cm，左右 2.8cm |
| 主标题 | 黑体 二号（22pt）居中 |
| 信息行 | 楷体 四号（14pt）居中 |
| 一级章节 | 黑体 三号（16pt） |
| 二级小节 | 黑体 四号（14pt） |
| 正文 | 仿宋_GB2312 小四（12pt），首行缩进 2 字符，1.4 倍行距 |
| 表格正文 | 宋体 五号（10.5pt） |
| 表头 | 黑体 五号 + 浅蓝底纹 |
| 引用块 | 楷体 11pt 灰字，◆ 前缀，左缩进 |
| 页脚 | 第 X 页（自动页码域）居中 |
| 附录 | 自动另起一页 |

## 四、调用方法

```bash
python3 scripts/build_docx.py 输入.md [输出.docx]
```

- 输出路径缺省：与输入同名 .docx
- 转换成功输出 `[ok] 已生成：路径`
- 出现 `[warn]` 提示：检查 Markdown 是否符合本约定

## 五、常见错误对照表（质检第 8 维使用）

| 错误写法 | 后果 | 正确写法 |
|---------|------|---------|
| `情境导入(5分钟)→实验探究(8分钟)→…` 横排箭头 | Word 中错位、残留竖线（本次修复的核心问题） | 用"思路主线"两列表格 |
| 教案中插入 `![](截图.png)` | 图片尺寸失控、破坏版面 | 图片素材只读信息，文字转述融入设计 |
| 表头写成 `学生活动` 等自创名称 | 列宽规则不触发 | 逐字使用"环节流程（学生做什么）"等标准表头 |
| `#` 用了多个 | 排版层级混乱 | 主标题仅一个，其余用 `##`/`###` |
| 用 `---` 分隔章节 | 渲染不一致 | 章节自然由 `##` 标题分隔 |
| 信息行超 40 字 | 自动降字号仍可能拥挤 | 拆成两行 `@info`，每行 ≤32 字 |
| 表格单元格内用 `<br>` 手动换行 | 部分播放器不识别 | 交给自动换行，控制每格文字量 |

## 六、生成前自检清单（Step 4 组装完 Markdown 后逐项核对）

- □ `# 主标题` 全文仅 1 个，位于第 1 行
- □ `@info` 共 2 行，每行 ≤32 字
- □ "思路主线"表：两列、5±2 行、每环节名含"（X分钟）"
- □ 每个环节四列表的表头与标准表头逐字一致
- □ 每个环节表格后都有"信息技术应用"引用块（不用技术也写明理由）
- □ 全文无图片语法、无代码块、无 `→` 横排流程图
- □ 附录标题含"附录"二字（触发分页）
- □ 文件名：`教学设计_[课题名称].md` / `.docx`
